# telegram-reminder

Бот раз в день отправляет одно и то же сообщение в рабочую группу Telegram в 19:00, 20:00 и 21:00. Процесс в контейнере не завершается. Политика `restart: unless-stopped` поднимает его снова после перезагрузки сервера, если демон Docker включён в автозагрузку.

Секреты в образ не попадают. Токен и id группы берутся из `.env`, текст — из `message.json` на хосте.

## Запуск на сервере

На машине должен быть установлен Docker Engine и плагин Compose. Демон Docker — в автозагрузке:

```bash
sudo systemctl enable --now docker
```

Дальше:

```bash
git clone <url-репозитория> telegram-reminder
cd telegram-reminder
cp .env.example .env
cp message.example.json message.json
```

В `.env` указать:

- `BOT_TOKEN` — токен бота от BotFather
- `CHAT_ID` — id группы (у супергрупп обычно начинается с `-100`)
- `TZ` — часовой пояс группы, имя из базы IANA. Для UTC+6 это, например, `Asia/Omsk`
- `SEND_HOURS` — часы отправки. По умолчанию `19,20,21`

В `message.json` — текст:

```json
{
  "text": "Текст напоминания"
}
```

Необязательное поле `parse_mode` (`HTML` или `Markdown`) включает разметку Telegram.

Файл `message.json` нужно создать до первого запуска. Если его нет, Docker создаст на этом месте каталог, и контейнер не увидит текст.

Одна команда запуска:

```bash
docker compose up -d --build
```

Проверка:

```bash
docker compose logs -f
```

В логе при старте есть часовой пояс и время следующего слота.

Внутри запланированного часа сообщение уходит один раз. Если контейнер в этот час перезапустился уже после успешной отправки, повторной отправки не будет: слот записан в том `reminder-data`. Если весь час контейнер был выключен, этот слот пропускается. Если отправка не удалась, попытки повторяются до конца этого часа.

Текст в `message.json` перечитывается при каждой отправке, пересборка для смены текста не нужна. Смена `.env` требует пересоздания контейнера:

```bash
docker compose up -d
```

Остановка без удаления истории слотов:

```bash
docker compose down
```
